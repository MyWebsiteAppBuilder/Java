Built-in types

byte, short, int and long

| Type | Encoding method | Length | Range | Default value |
| --- | --- | --- | --- | --- |
| byte  | two's complement | 8 bit  | [-2<sup>7</sup>, 2<sup>7</sup>-1]   | 0  |
| short | two's complement | 16 bit | [-2<sup>15</sup>, 2<sup>15</sup>-1] | 0  |
| int   | two's complement | 32 bit | [-2<sup>31</sup>, 2<sup>31</sup>-1] | 0  |
| long  | two's complement | 64 bit | [-2<sup>63</sup>, 2<sup>63</sup>-1] | 0L |

An integer literal is of type int by default. The compiler will raise the "integer number too large" error when you attempt to create a long typed literal without the "L" suffix.

Integer literals can be expressed by three number systems: decimal, hexadecimal and binary.

float and double

| Type | Encoding method | Length | Range | Default value |
| --- | --- | --- | --- | --- |
| float  | IEEE 754 | 32 bit | ? | 0.0F |
| double | IEEE 754 | 64 bit | ? | 0.0  |

The float type and the double type should never be used for precise values, such as currency. For that, you will need to use the java.math.BigDecimal class instead.

A floating-point literal is of type double by default. The compiler will raise the "possible lossy conversion from double to float" error when you attempt to assign a double typed literal to a float typed symbol.

Floating-point literals can also be expressed using "e".
